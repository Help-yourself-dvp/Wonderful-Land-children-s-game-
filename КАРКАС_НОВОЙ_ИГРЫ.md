## 4. ФИКСИРОВАННЫЕ ТЕХНИЧЕСКИЕ РЕШЕНИЯ

- **Стек:** Three.js (~0.160) + Vite 5 + Capacitor 6, сборка APK в GitHub Actions. Без фреймворков UI.
- **Структура:** `index.html` (вся разметка + CSS), `src/main.js` (вся логика; однофайловый MVP —
  доказано рабочим), `src/audio.js` (синтез Web Audio + голосовые mp3), `public/voice/*.mp3`,
  `public/art/*.webp`, `tools/build_preview.py`, `tools/shot/` (Playwright), `version.txt`.
- **Версия — один источник:** `version.txt`; `package.json`/lock должны совпадать; Vite подставляет
  номер в HTML (`__APP_VERSION__`); workflow задаёт Android `versionName`, а `versionCode` — монотонный
  `github.run_number`. CI падает при рассинхронизации.
- **Android:** только landscape (`screenOrientation="landscape"`), fullscreen immersive
  (FLAG_KEEP_SCREEN_ON + Wake Lock — экран не гаснет), **ноль разрешений**, ноль сети.
- **Подпись APK:** стабильный debug-keystore в секрете CI `DEBUG_KEYSTORE_BASE64`; в `build.gradle`
  жёстко прописан `signingConfigs.debug` (иначе gradle молча генерирует новый ключ и обновления
  «поверх» перестают ставиться). Эталон отпечатка храни в `expected_cert.txt`; сравнивать
  ТОЛЬКО fingerprint сертификата (хэш сырого CERT.RSA меняется каждую сборку из-за метки времени).
- **Офлайн-превью:** `python3 tools/build_preview.py` инлайнит JS-бандл, все mp3 (base64) и арты
  в один HTML — пользователь открывает его в просмотрщике БЕЗ сети.
- **Скриншоты:** `tools/shot/shoot.mjs` (Playwright-core + @sparticuz/chromium; в песочницах без
  системного Chromium). Хуки-сцены в коде: `#shot-<имя>` и портреты `#solo-<зверь>`. В walk-режимах
  раз в секунду пиши DBG-лог позиции героя в консоль — проверяй движение по логам, а не по кадрам.
- **Арт:** генерируй 16:9, конвертируй в WebP 1600×900 quality≈82 (≈60–170 КБ на файл); суммарный APK
  держи ~8–10 МБ. По одной картинке за заход. Референсы пользователя в git НЕ класть.
- **Полигоны:** ≤15 000 на сцену; 1 Ambient + 1 Directional; тени — только blob-кружки; 60 FPS на
  средних, 30 на старых устройствах.

## 5. ПРОДУКТОВЫЕ ПРИНЦИПЫ ДЛЯ ДЕТЕЙ 3–6 (НЕ НАРУШАТЬ)

- **Zero Fail:** неверный ответ = мягкий «плинг» + покачивание + новая попытка. Никаких ругательств,
  штрафов, «ВЫ ПРОИГРАЛИ». Победа всегда достижима.
- **Авто-сложность по возрасту:** один переключатель 3–4 / 5–6 лет (на заставке и в родительском
  уголке). Меняется объём и длина заданий, не правила: 3–4 → меньше предметов/раундов/вариантов.
- **Подсказки:** свечение верного элемента через ~20 с простоя, пальчик-указатель через ~28 с.
- **Голос несёт смысл** (ребёнок 3–4 лет не читает): каждое задание озвучивается. **Слова ≡ картинке:**
  переменное содержимое выбирается ДО озвучки, у каждого варианта свой mp3.
- **Ничего страшного:** никаких монстров/наказаний/пугающих слов; «враги» — только добрые шутники
  (в эталоне — волки-«щекотуны»).
- **День/ночь** в мире (~5 минут на цикл); ночью всё спокойное, волшебное.
- **Родительский уголок** за «взрослой» задачкой (пример): статистика, возраст, таймер отдыха
  («Доброе ограничение» — мягкая карточка, без «ВРЕМЯ ВЫШЛО»), сброс прогресса с удержанием 2,5 с.
- **Мета-прогрессия** (как в эталоне): задание → капелька → полив Древа → наклейка в альбом.
- **Совет участников** для любого видимого текста: прогони глазами 4 персон (Психолог 3–6 / Родитель /
  Маркетолог / Критик) и прими компромисс. Без штампов, капса и «малышовых» инфантилизмов.
- **Награда ≠ взятка:** хвали действие («как аккуратно!»), не личность, и не перехваливай.

## 6. АРХИТЕКТУРА КОДА (проверенные контракты)

- **Локации в одной сцене:** `LOCS = [{x,z,name,sub}, ...]` — острова с шагом 150 по z; навигация
  A* 64×64 пересчитывается от `LOCS[curLoc]` (`navOX/navOZ`); препятствия — в мировых координатах.
- **Порталы:** обобщённая цепочка `PORTAL_DEFS = [{ obj, loc, dest, appr }]`; тап по арке →
  `pendingPortalDef` → подход (`appr`) → `travelTo(dest)`; шторка-переход; `LOC_EXIT[dest]` — точка
  высадки. Не хардкодить «туда-обратно» — цепочка работает на N локаций.
- **NPC-фабрики:** `makeX()` возвращает `THREE.Group` с контрактом `userData` (например
  `{ head, lamp, eyes:[L,R], glints:[L,R], body, tail, ... }`) — анимации в `animate()` читают ТОЛЬКО
  эти ключи. Менять модель можно, контракт — нельзя. Глаза моргают отдельными таймерами
  (`xBlinkT`); геройский блинк (`charData.eyes`) — отдельно.
- **Мини-игра = DOM-карточка:** `<div id="Xgame">` c `.mg-card` (тёплая рамка), `.mg-field`/`.X-field`
  16:9 с фоном-артом, кнопка 💡, универсальная кнопка выхода ✕ (`makeExitButton`), `gameState='xgame'`
  (всё не-explore = мини-игра, мир и волки на паузе автоматически). Логика — объект-состояние
  `const x = {...}` с `lastAction`, `slow`, `fingerShown` для таймингов подсказок.
- **Диалог NPC:** тап → если далеко: pending-флаг + `givePath` (подход); пришли → `startXDialog()`:
  `gameState='dialog'`, `dialogToken` (гонки), `speak(hello|again)`, `speak(ask, {after:true})`,
  таймер → `openXGame()`. Победа → `celebrateX()`: капелька, `onTaskDone()`, `wm_met_x=1`, фанфары,
  win-голос, конфетти, возврат в мир.
- **Случайность с фиксированными сидами:** общий `rand()` для Л1 не трогать; каждой новой локации —
  свой генератор (`r2`, `r3`, seed-константа), иначе переезжает вся рассадка мира.

## 7. АУДИО-ПРАВИЛА

- Голоса NPC — синтезированные mp3 в `public/voice/`, локально, офлайн. SFX — Web Audio синтез.
- Имена файлов: `<зверь>_hello.mp3` (первая встреча), `<зверь>_again.mp3` (повтор), `<зверь>_ask.mp3`
  (задание), `<зверь>_win.mp3` (победа). Ударения — знак U+0301 (например «дружо́к»).
- `speak(file)` — новая реплика обрывает предыдущую; `speak(b, {after:true})` — очередь;
  цепочка из трёх — `speak(b, {after:true, then:c})`. **Ловушка:** в ветке немедленного
  воспроизведения перезахватывай поколение `gen = voiceGen` ПОСЛЕ `stopVoice()`, иначе цепочка
  молча гаснет.
- **Единый диктор на главу:** все закадровые реплики одной главы — один голос. Новые mp3 в
  существующую главу — тот же голос (сверка кандидаток НА СЛУХ; регистрации голосов между
  сессиями не сохраняются).
- Новые персонажи = новые голоса через прослушивание (пользователь голосует между 2 кандидатами).
- Все mp3 ОБЯЗАТЕЛЬНО коммитить в git.

## 8. ИЗВЕСТНЫЕ ГРАБЛИ (не наступать повторно)

1. **Песочница пересоздаётся** между диалогами: всё вне репозитория стирается. Инструменты — только
   в репозитории (`tools/`); восстановление: `npm install` + `(cd tools/shot && npm i && node unpack-libs.mjs)`
   + `npm run build && python3 tools/build_preview.py`.
2. **SwiftShader рендерит 4–10 fps**, игровое время идёт по кадрам (dt=1/60) → всё в 6–15 раз медленнее;
   setTimeout запаздывают. Никогда не суди «зависло» по кадру — жди по логам/позициям дольше.
3. **Эмодзи в headless-скриншотах** могут не отрисовываться (нет шрифтов) — это не баг игры.
   Интерактивные элементы не строить на эмодзи (Android-шрифты разные) — CSS-формы или SVG.
4. **WebP в CSS:** `background: <fallback-цвет> url('./art/x.webp') center/cover no-repeat;`.
   PNG-референсы в `public/` не оставлять.
5. **CSS-сетки:** спейсеры скрывать `visibility:hidden`, а НЕ `display:none` (последнее ломает сетку).
6. **Прятки элементов:** прятать СЖАТИЕМ/scale в центре своего контейнера, а не translate вниз —
   иначе «падает за край экрана» (урок второго этапа Крота).
7. **Превью-инлайн:** JS вставляется как `<script type="module">`; замены в скрипте — строковые,
   не `re.sub` (минифицированный JS содержит `\w`/`\d`).
8. **GitHub:** `release_target` — только ПОЛНЫЙ 40-значный SHA (короткий ломает релиз); логи/артефакты
   иногда рвутся EOF — не повторять одинаковые скачивания, сверять по API; загрузка ассетов из
   песочницы может обрываться EOF — публикацию делает CI-раннер (`publish_release=true`).
9. **Playwright-клики** по анимированным кнопкам — с `{ force: true }` (иначе вечное «element is not stable»).
10. **Голосовые цепочки** — см. раздел 7 (voiceGen после stopVoice).
11. **Альбом/сюжетные гейты:** новые NPC не добавлять в списки сюжетных условий, если сюжет
    считает «всех шестерых» — иначе старые сохранения ломаются.
12. **Один заход — одно большое дело**: одна мини-игра или одна сцена за ответ; в конце — коммит,
    чтобы следующий ИИ подхватил всё из git.

## 9. РЕЛИЗНЫЙ КОНВЕЙЕР

1. Поднять `version.txt` (+ package.json/lock). 2. Обновить RELEASE_NOTES.md и все документы.
3. Прогнать чек-лист (ниже). 4. Пуш в ветку сессии. 5. Запуск workflow вручную или ИИ:
   `publish_release=true`, `release_target=<полный SHA>`. 6. CI: сборка → подпись → сверка отпечатка →
   GitHub Release с APK `wonder-<имя>-<версия>.apk`. 7. Проверить: conclusion=success, тег на нужном
   SHA, ассет ненулевой, отпечаток в теле релиза == эталону. 8. Ссылки в README/ЧЕКЛИСТЕ — на новый APK.
- Обновление «поверх» сохраняет прогресс (localStorage), если не удалять приложение; версии с другой
  подписью — только через удаление (один раз предупредить).

## 10. ЧЕК-ЛИСТ ПРИЁМКИ АЛЬФЫ/БЕТЫ (повтори в новом проекте как ЧЕКЛИСТ_ТЕСТОВ.md)

1. Установка APK, старт без сети, версия видна на заставке и в «О приложении».
2. Горизонтальный режим; портретная подсказка «поверни устройство» (веб) / лок на Android.
3. Каждая мини-игра: открытие, полное помещение на 812×375 и 1280×800, кнопки 💡 и ✕,

7. Мир: движение без застреваний, препятствия обходятся, день/ночь, пауза замирает ВСЁ.
8. Прогресс переживает перезапуск и обновление поверх.
9. 0 console/page-ошибок в Playwright; превью собрано и открывается у пользователя.
10. Документы обновлены; всё закоммичено; релиз опубликован с проверенным отпечатком.
